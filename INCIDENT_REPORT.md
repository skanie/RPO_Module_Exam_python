# INCIDENT_REPORT.md - NexusMonitor

Отчет об устранении инцидентов в системе NexusMonitor

## Инцидент №1: Неправильная конфигурация пути логирования

──────────────────────────────────

**СИМПТОМ:**
   При запуске бэкенда приложение падает с ошибкой permission denied при попытке создать директорию `/var/log/nexus_monitor_production/`. Система не может запуститься на локальной машине разработчика.

**ПРИЧИНА:**
   В файле `backend/core/logging_config.py` жестко закодирован путь логирования `/var/log/nexus_monitor_production/`, который требует прав администратора и недоступен в локальной среде разработки. Этот путь был настроен для боевого сервера, но по ошибке остался в коде разработки.

**РЕШЕНИЕ:**
   Изменен путь логирования на локальную директорию `backend/logs/`, которая будет создаваться относительно проекта и не требует специальных прав. Код обновлен в файле `backend/core/logging_config.py`.

**КОММИТ:**
   fix(logs): change logging path to local development directory

## Инцидент №2: Отсутствие правильной конфигурации API URL

──────────────────────────────────

**СИМПТОМ:**
   Фронтенд не может подключиться к API. При открытии приложения в браузере (localhost:5173) консоль выдает ошибку CORS или неверный URL. Фронтенд пытается обратиться к API, но запрос падает.

**ПРИЧИНА:**
   В файле `frontend/src/App.jsx` используется переменная окружения `import.meta.env.VITE_API_URL`, однако путь в файле `frontend/.env` не совпадает с реальным API эндпоинтом. API находится на `http://localhost:8000/api`, но фронтенд пытается обратиться с неправильным путем.

**РЕШЕНИЕ:**
   Исправлен путь API URL в `frontend/.env` на корректное значение `VITE_API_URL=http://localhost:8000/api`. Проверено, что фронтенд правильно использует эту переменную в `fetch()` запросе.

**КОММИТ:**
   fix(api): correct frontend API endpoint configuration

## Инцидент №3: Отсутствие правильной обработки окружения в конфигурации

──────────────────────────────────

**СИМПТОМ:**
   Приложение может запуститься, но при попытке подключиться к базе данных выдает ошибку о невозможности загрузить переменные окружения из `.env` файла. Класс `Settings` из pydantic не находит необходимые перемен��ые.

**ПРИЧИНА:**
   В файле `backend/core/config.py` класс `Config` указывает `env_file = ".env"`, но путь относительный и может не совпадать с рабочей директорией при запуске из разных мест. Класс Settings требует обязательные переменные, но они не загружаются корректно.

**РЕШЕНИЕ:**
   Обновлен файл `backend/core/config.py` с использованием `BaseSettings` из pydantic_settings и добавлены значения по умолчанию для локальной разработки. Убедитесь, что файл `.env` находится в директории `backend/` и содержит все необходимые переменные окружения.

**КОММИТ:**
   fix(env): update settings configuration to properly load environment variables

## Инцидент №5: Отсутствие обработки ошибок при подключении к БД

──────────────────────────────────

**СИМПТОМ:**
   При отсутствии подключения к PostgreSQL приложение просто падает без понятного сообщения об ошибке. Нет никакого feed back пользователю.

**ПРИЧИНА:**
   В файле `backend/main.py` и `database.py` отсутствует обработка ошибок подключения к базе данных. Если База данных недоступна, система не выдает полезной информации об ошибке.

**РЕШЕНИЕ:**
   Добавлена базовая проверка подключения к БД при запуске приложения. Функция `get_db()` содержит обработку исключений с логированием ошибок. Это позволяет быстро идентифицировать проблемы с БД при запуске.

**КОММИТ:**
   fix(api): add database connection error handling and logging
